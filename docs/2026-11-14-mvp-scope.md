# Expert Witness Email Search MVP Scope

Date: November 14, 2026

Status: Initial scope baseline. The user accepted the high-level direction for further discussion. Technical design, detailed acceptance criteria, and the decision to build versus use an existing product remain open.

## Purpose

Help expert witnesses locate and review relevant source material within large Outlook email archives spanning years. The expert should be able to investigate a topic, follow related conversations, and understand who communicated with whom and how those people relate to the case.

AI may help develop the software. The MVP must use non-AI processing and search, with no model-generated interpretation, summaries, or restatements of email evidence. The expert makes the findings and draws conclusions.

## Initial MVP Objectives

1. Import large Outlook archives and prepare their messages for searching. The input format must be confirmed from actual files. Outlook exports commonly use PST; OST is a distinct offline data format. [Microsoft format guidance](https://support.microsoft.com/en-us/outlook/create-an-outlook-data-file-pst-to-save-your-information)
2. Provide a useful improvement over basic Outlook search, combining terms and topics with people, dates, and conversation relationships.
3. Thread related messages so an expert can follow a conversation and its participants over time.
4. Present messages clearly, reducing distracting formatting and repeated material.
5. Support relationships between messages, correspondents, case roles, and topics of interest. The method of assigning and maintaining these relationships remains to be designed.
6. Run locally on Mac or Windows, with the initial platform and packaging still undecided.

Background processing that prepares results for review the following day is an option to investigate. It is not yet an agreed turnaround target or a requirement that every search run overnight.

## Candidate Search Capabilities

These are options to evaluate, not a committed feature list. Comparable products document many of them in the [product research](2026-11-14-product-research.md).

| Search method | Potential use |
| --- | --- |
| Keywords and exact phrases | Find a named subject, project, issue, or quoted expression. |
| Boolean combinations and exclusions | Combine alternative terms and exclude known irrelevant matches. |
| Proximity | Find two terms close together in a message. |
| Metadata filters | Limit by sender, recipient, date range, subject, source archive, or attachment information. |
| Wildcards and word variants | Include related spellings or word endings. |
| Fuzzy matching | Find possible misspellings while making the expanded matching behavior visible. |
| User-defined term lists and synonyms | Associate a topic with explicit terms and abbreviations chosen by the expert. |
| Identity and case-role filters | Search across confirmed email aliases or a user-assigned role in the case. |
| Conversation expansion | Inspect surrounding messages in a thread after finding a relevant hit. |
| Attachment search | Search filenames or extracted attachment text, if included in the MVP. |

## Proposed Evidence Handling

Keep original source material accessible and link each displayed message back to its source. A cleaned reading view would preserve original wording while allowing formatting, signatures, and repeated quoted material to be collapsed. The exact rules and original-message access need review before implementation.

Treat "consolidate and explain" as a request to organize source messages, dates, participants, and matching passages into an understandable sequence. Automatically rewriting substantive jargon or generating an account of what happened would conflict with the no-AI MVP boundary. The final reading behavior remains to be agreed.

## Later Roadmap

- Hosted archive uploads, processing, and review with production access controls and data protection.
- Flagging searches and their result sets.
- Flagging documents and manually relating them to topics, targets, and reports.
- Bug reporting within the application.
- Estimated time savings and actual review-time tracking for billing.
- Optional AI analysis in a separately considered future phase.

Detailed cloud infrastructure and production security design are outside the immediate MVP discussion. Local storage and source-preservation requirements still need definition.

## Questions Before Technical Design

- What concrete question should the expert answer that ordinary Outlook search handles poorly?
- What file formats, archive sizes, message counts, and number of mailboxes will the first case contain?
- Which operating system and hardware will be used first?
- Must attachment contents be searched, and which attachment types matter?
- Who assigns identities, aliases, case roles, and topic terms, and how should corrections work?
- What should a readable conversation include, and how should uncertain thread connections appear?
- What import completeness, search accuracy, responsiveness, and background-job behavior will define success?
- Which requirements remain unmet after evaluating existing products?
